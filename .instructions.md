# Agent Instructions — [Project Name]

## Prime directive
Do not invent product intent. Use PRODUCT_SOT and initiative plans as the contract.

## Repo workflow
1) Read `/docs/PRODUCT_SOT.md`
2) Identify the active initiative under `/docs/INITIATIVES/`
3) Implement only what the initiative scopes
4) Update initiative PLAN with progress + decisions

## Non-destructive policy
- Default to additive changes.
- Do not overwrite existing code unless the initiative explicitly asks.
- Prefer extending over replacing.

## Code quality standards
- Write tests for new functionality
- Follow existing code style and patterns
- Add proper error handling and logging
- Update documentation for API changes

## Initiative workflow
- Mark tasks complete in PLAN.md as you finish them
- Add decisions and rationale to the PLAN
- Note any assumptions or risks discovered
- Update acceptance criteria if scope changes

## Documentation standards
- Keep PRODUCT_SOT current with product decisions
- Update ARCHITECTURE.md for structural changes  
- Use clear, specific language over vague descriptions
- Include examples and use cases where helpful

## Quality checks
Before marking an initiative complete:
- All acceptance criteria are met
- Tests pass and coverage is maintained
- Documentation reflects current state
- No breaking changes without migration path

# README Template Guide

This is a template and guide for writing effective initiative README.example.md files.

## Required sections

### Initiative title and purpose
Use the format: `# I[N] — [Short descriptive title]`

### Outcome
**What this section should contain:**
- Clear statement of what this initiative will deliver
- The end state after completion 
- Focus on the value/benefit, not just activities

**Example:**
> A commit-ready repository structure with base + supabase templates, and v1 documentation framework for this project.

### Scope
**What this section should contain:**
- What is explicitly included in this initiative
- Specific deliverables and activities
- Clear boundaries of what will be done

**Template:**
[What is included in this initiative]
- [Deliverable 1]
- [Deliverable 2] 
- [Deliverable 3]

### Non-scope
**What this section should contain:**
- What is explicitly not included
- Items that might be expected but are deferred
- Helps prevent scope creep

**Template:**
[What is explicitly not included]
- [Thing we're not doing]
- [Feature deferred to later]

### Acceptance criteria
**What this section should contain:**
- Specific, measurable criteria for completion
- Each criterion should be testable/verifiable
- Should align with the outcome statement

**Template:**
[Specific, measurable criteria that must be met for this initiative to be considered complete]
- [ ] [Criterion 1 - specific and testable]
- [ ] [Criterion 2 - specific and testable]  
- [ ] [Criterion 3 - specific and testable]

## Best practices

**Writing effective outcomes:**
- Focus on business value, not just technical completion
- Should answer "why does this matter?"
- Keep it concise but complete

**Scoping well:**
- Be specific about deliverables
- Use active verbs ("Create X", "Implement Y", "Configure Z")
- Break large scope down into logical groups

**Creating good acceptance criteria:**
- Each criterion should have a clear pass/fail test
- Avoid vague terms like "good" or "stable" without definition
- Should cover all aspects of the outcome
- Typically 3-5 criteria for most initiatives

**Common mistakes to avoid:**
- Vague outcome statements that could mean anything
- Scope that's really just a task list
- Acceptance criteria that can't be objectively verified
- Missing non-scope that leads to scope creep
